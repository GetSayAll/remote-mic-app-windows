# 0.2.3 升级后应用未响应

- 发现日期：2026-09-09
- 状态：已修复，等待 RC001/RC003 真机验证
- 影响范围：从 0.2.2 升级到 0.2.3；Windows；与遥控器型号和第三方工具无关
- 功能点：WASAPI 音频运行时、启动状态读取、结构化日志
- 现象：应用窗口启动后约两秒进入未响应状态，页面无法正常交互。
- 复现条件：0.2.3 已保存音频输出端点，应用启动期间触发音频中断清理，随后前端读取首次运行状态。
- 正常预期：音频中断清理和首次运行状态读取均应及时完成，页面保持响应。
- 证据：0.2.3 release 构建可重复出现窗口未响应；诊断日志显示音频端点恢复完成，首次运行状态停在 `checkpoint=audio`；Wait Chain Traversal 显示 UI 线程处于阻塞等待；最小代码实验确认音频中断日志进入后无法完成第二次状态锁定。
- 根因：0.2.3 新增的音频中断日志在同一个 `format!` 语句中两次锁定同一个非重入 `Mutex`。第一个 `MutexGuard` 临时值在语句结束前仍存活，第二次锁定使 WASAPI 工作线程自死锁；同步的首次运行状态读取随后等待同一把锁，使窗口表现为未响应。
- 修复：在一次锁定中读取日志所需的 `generation` 和 `submitted_samples`，释放锁后再格式化日志；保留首次运行状态检查点用于区分未来的启动 IPC 故障。
- 验证：`interrupt_logging_does_not_deadlock_the_audio_worker` 回归测试为 `passed`；内嵌前端的 0.2.3 release 构建为 `passed`；保留已保存音频端点启动后连续观察 15 秒，窗口始终响应，音频中断、首次运行状态、Vue 挂载均记录完成终态，原始复现为 `passed`。RC001/RC003 真机验证为 `deferred`。
