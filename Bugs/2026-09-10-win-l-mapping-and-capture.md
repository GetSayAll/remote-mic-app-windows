# Win+L 映射不锁屏、录入时反而锁屏

## 现象

- 电源单击映射为左 Win+L 后，按遥控器没有锁屏。
- 在“录入自定义快捷键”中按左 Win+L，Windows 先执行锁屏，组合键无法完成录入。

## 根因

1. 执行端把所有动作统一视作前台键盘输入，Win+L 依赖 Shell 对注入边沿的识别；系统锁屏已有更直接、公开且不依赖前台窗口的 `LockWorkStation` API。
2. 录入端仅在 WebView 的 `keydown` 里调用 `preventDefault`。该事件到达页面时已经晚于系统级快捷键处理，无法保护 Win+L。

## 修复

- 精确的左/右 Win+L 映射改走 `LockWorkStation`；返回值和耗时写入结构化诊断日志。
- 常驻低级键盘钩子增加显式、短生命周期的录入模式，在 Windows 处理前成对吞下物理边沿，并经有界通道/独立事件线程回传界面。
- 录入开始前已按住的键继续完整放行；录入结束后的自动重复 DOWN 和最终 UP 继续完整吞下，避免粘键。
- 页面退出、切换编辑格、取消和 15 秒超时统一停止录入。

## 验证

- 前端组件测试：原生边沿 `LeftWindows DOWN → L DOWN` 保存为左 Win+L，并停止录入。
- Rust 单元测试：左右修饰键转换、精确锁屏动作识别、录入结束后的 DOWN/UP 配对，以及钩子重启后的孤立 UP 放行。
- Windows 编译和真实 API 链路：待本地测试包与现场按键复验记录。
