# Win+L 映射不锁屏、录入时反而锁屏

## 现象

- 电源单击映射为左 Win+L 后，按遥控器没有锁屏。
- 在“录入自定义快捷键”中按左 Win+L，Windows 先执行锁屏，组合键无法完成录入。
- 初版修复现场复验：录入能够保存但松键前停止保护，随后仍会锁屏；遥控器锁屏后
  释放沿延迟约 10–12 秒，下一次按下偶发被旧按住态去重，需要按第二次。

## 根因

1. 执行端把所有动作统一视作前台键盘输入，Win+L 依赖 Shell 对注入边沿的识别；系统锁屏已有更直接、公开且不依赖前台窗口的 `LockWorkStation` API。
2. 录入端仅在 WebView 的 `keydown` 里调用 `preventDefault`。该事件到达页面时已经晚于系统级快捷键处理，无法保护 Win+L。
3. 锁屏会切换交互会话，遥控器 UP 可能直到解锁后才交付；映射引擎若等待该 UP
   才清除状态，锁屏后的首个新 DOWN 会与旧状态合并。
4. 录入初版在收到终止键 L 的 DOWN 后立即停用录入，早于 Win/L 的配对 UP，
   系统组合键保护窗口不完整。
5. 第二轮现场逐键日志确认 Win/L DOWN 均被本钩子判定为吞下，但仍在 69–128ms
   后锁屏，且没有映射执行日志。这排除了页面与本应用映射动作，证明当前主机上的
   Win+L 系统保留路径不能由普通用户态钩子可靠屏蔽。
6. 尝试在录入开始时刷新钩子链首后，命令虽在 1–3ms 内报告重挂成功，但现场
   Win/L 边沿完全未进入新钩子，既锁屏又无法保存；该方案被证伪并回退。
7. v0.2.6 现场发现：`LockWorkStation` 在电源 DOWN 沿立即启动异步桌面切换，
   实体键的 UP 尚未被门控成对消费。该迟到边沿跨到锁屏/解锁阶段后，Windows
   偶发执行原生浏览器动作并弹出“需要使用新应用打开 microsoft-edge 链接”。
   同时段日志只有 `Power → Win+L → LockWorkStation passed`，没有 `open_app`，
   当前映射也没有打开应用动作；先等待实体 UP 的初版修复仍会复现，因此该归因
   已被后续实测证伪。
8. 2026-09-12 最终取证：问题的必要前序是 TV 键，TV DOWN/UP 已被门控成对吞下，
   泄漏计数不增长；随后即使等待 15 秒再锁屏仍会弹窗。进程探针确认
   `LockWorkStation` 成功约 4 秒后由系统服务创建 `OpenWith.exe`，解锁后显示
   `microsoft-edge:` 协议选择器。100ms 轮询和 `EVENT_OBJECT_SHOW` 隐藏均偶发
   闪现；`EVENT_OBJECT_CREATE` 阶段终止精确的 `OpenWith.exe` 连续四轮没有
   可见窗口。结论：Windows 保留了 TV 的独立 Shell 协议动作，桌面切换使其落到
   缺失的 Edge 协议处理器；不是 Power/Win+L 边沿泄漏，也不是 SayAll 的
   `open_app`（现场 TV 映射目标为已运行的记事本）。

## 修复

- 精确的左/右 Win+L 映射改走 `LockWorkStation`；返回值和耗时写入结构化诊断日志。
- 常驻低级键盘钩子增加显式、短生命周期的录入模式，在 Windows 处理前成对吞下物理边沿，并经有界通道/独立事件线程回传界面。
- 录入开始前已按住的键继续完整放行；录入结束后的自动重复 DOWN 和最终 UP 继续完整吞下，避免粘键。
- 终止键按下后先保存组合键，但保持原生拦截；只有录入期间观察到的所有按键均
  已松开，才停止录入模式。
- 精确 Win+L 单击在 DOWN 沿只进入等待；合并后的真实 UP 到达、门控完成原始
  DOWN/UP 配对后才调用 `LockWorkStation`。普通快捷键仍在 DOWN 沿即时执行，
  双击/长按时序不变；动作成功后的状态清理保留为异常兜底。
- 观察到 TV 语义按压后，仅为下一次 SayAll 锁屏预装 15 秒
  `EVENT_OBJECT_CREATE` 钩子；钩子就绪后才调用 `LockWorkStation`。窗口创建
  回调只接受 Windows `System32` 下映像名精确为 `OpenWith.exe` 的进程并立即
  终止，阻止协议选择器进入 SHOW 阶段。无 TV 前序时不启用；其它窗口/进程不处理；全部分支写
  `open_with_guard` 结构化日志。
- 默认保留直接按完整组合的录入体验；另提供默认关闭的“安全录入模式”开关，并
  提示仅在直接录入失败或触发系统动作时使用。开启后用鼠标选择左/右修饰键，再
  只按一个主键（例如点击“左 Win”后单独按 L）；物理输入流从未形成 Win+L。
- 页面退出、切换编辑格、取消和 15 秒超时统一停止录入。

## 验证

- 前端组件测试：默认模式的物理 `LeftWindows DOWN → L DOWN/UP → LeftWindows UP`
  保存为左 Win+L；开启安全模式后，点击“左 Win”再输入 `L DOWN → L UP` 同样
  保存为左 Win+L，且输入流中不产生物理 Win 边沿。
- Rust 单元测试：左右修饰键转换、精确锁屏动作识别、录入结束后的 DOWN/UP 配对，以及钩子重启后的孤立 UP 放行。
- 手势与映射引擎测试：Win+L 在 DOWN 沿不执行、UP 沿执行；连续两次完整
  DOWN/UP 均触发，普通无连发单击仍保持 DOWN 沿即时执行。
- 链首刷新方案现场 failed（锁屏且不保存），已回退；安全组合录入的自动化测试
  passed，安装后的现场复验 deferred。
- Windows 编译和真实 API 链路：待本地测试包与现场按键复验记录。
- `OpenWith` 兜底原型现场：SHOW 阶段拦截四轮仍有一轮闪白，failed；CREATE
  阶段连续四轮均无弹窗/闪白，passed。产品化代码自动化 passed，安装包复验
  deferred。
