# 豆包右 Alt 语音键错误切换到微信输入法

- 发现日期：2026-09-29
- 状态：RC003 安装版真机通过；切回微信的独立关闭态缺陷见 `2026-09-30-switching-doubao-to-wetype-keeps-right-alt-synth.md`
- 影响范围：Windows 11、0.3.0 本地测试包、RC003、豆包输入法；默认微信输入法快捷键路径不受影响
- 功能点：可配置的按住说话快捷键、输入法激活与 RC003 报告层合成
- 现象：把按住说话快捷键设为右 Alt 后，按遥控器语音键会先把当前输入法切成微信输入法，豆包语音条因此无法启动；隐藏自定义录入入口时也没有显式的豆包预设可切回。
- 复现条件：按住说话快捷键为单键右 Alt，豆包是当前输入法，RC003 语音键进入 `StreamStarted`。
- 正常预期：右 Alt 只驱动 RC003 报告层 `0x003E → 0x00E6` 合成与既有 ATVV 按下/释放生命周期，不激活或复活微信输入法；连接页始终提供“豆包输入法（右 Alt）”入口。
- 证据：
  - 现场观察：语音键按下后当前输入法变成微信输入法，豆包录音未启动。
  - 代码定位：`StreamStarted` 对任意已配置和弦都调用 `activate_wetype_session()`；合成不可用后的重试线程也未按和弦类型过滤。
  - 设置层确认：连接页自定义录入受功能开关隐藏，原页面只有微信默认预设与关闭，无法显式恢复右 Alt。
- 根因：微信输入法激活/复活逻辑错误地绑定到“存在任意按住说话快捷键”，而不是严格绑定到微信默认和弦“左 Ctrl + 左 Win”；同时缺少始终可见的豆包右 Alt 预设。
- 修复：
  - `ble.rs` 新增严格、顺序无关的微信默认和弦判定；只有该和弦进入微信激活、状态检查与重试，右 Alt记录 `ime_activation outcome=skipped reason=hotkey_not_wetype`。
  - 连接页新增始终可见的“豆包输入法（右 Alt）”预设，并沿用同一保存 IPC；“支持更多输入工具”继续与按键页“全按键支持”共享 `rc003_capture_enabled`。
- 验证：
  - Rust 单测 `wetype_activation_is_limited_to_the_wetype_default_hotkey`：`passed`。
  - 前端 `ConnectionPage.test.ts`：豆包预设显示与保存 `{ keys: ["right_alt"] }`：`passed`。
  - RC003 → 产品计划任务 Helper → RightAlt → 豆包语音条，且当前输入法不切到微信：`passed`（2026-09-30，操作人确认“豆包语音条正常”）。
  - RC001、冷/闲置首用、快速连按、断连与睡眠恢复：`deferred`。
