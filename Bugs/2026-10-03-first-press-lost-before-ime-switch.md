# 语音键第一按丢失：报告层合成先于输入法切换呈现（「按了好几次才出来」）

- 发现日期：2026-10-03（用户现场反馈 + 应用诊断日志；本地测试包 0.5.0 / main `0282dc1`）
- 状态：已实现修复（报告层有界延迟 + 应用能力声明）；**真机复测 deferred**
- 影响范围：Windows 11、RC003 + 豆包输入法、报告层合成路径（「全按键支持」开启时）。
  触发面 = **按下前系统活动输入法不是豆包** 的每一次按下（重启/升级后、切过窗口之后最常见）；
  表现为第一按（或前几按）拉不起豆包语音条，补按后恢复。RC001 未启用增强捕获时不走该路径。

## 现象与日志证据

应用诊断日志（UTC；本地 = UTC+8），2026-10-03 04:45:41（本地 12:45）一轮 5 次按压（session=110..114）：

- `session=110`：`41.640` 报告层**已把这一按改写成右 Alt 发出**
  （`synth:frame replace ok to=0xe6`）；`41.654` 应用查询 `active_is_target=false`
  （豆包不是活动输入法）；`41.705` 应用切换豆包**完成**
  （`ime_activation outcome=switched elapsed_ms=53`）。
  ⇒ 右 Alt 按下沿比切换完成早约 65ms 发出，**该按落在豆包激活之前，第一按丢失**。
- `session=111..114`：`active_is_target=true`，每次替换与音频会话都完整——链路本身健康。
- 按压时长与补按模式（5 连按、≈2s 间隔）与用户「按了好几次才出来」一致。

## 根因

设计事实（`crates/sayall-windows/src/ble.rs` 既有注释，2026-10-01 起）：报告层合成在设备
报告帧通过时**立即**改写（早于应用知情约一个 BLE/GATT 往返），而「切输入法」由应用在
得知按下后执行（实测 53ms）。同一按内两者赛跑：**合成先行、切换后到**，目标输入法
看不到按下沿。既有注释已把该行为写成「这一次切换是为**下一次**按下生效」——本 bug
就是它的用户可见面。

## 修复（方案 A：报告层有界延迟，应用声明后启用）

- 应用在桥接 hello 声明能力（`W 1`）；助手据此给 agent 下发 `gate` 命令（开/关，幂等）。
- agent 在语音键**按下帧**（`synthSeen`）、且租约/模式/清键上限检查都通过后，
  **先 `Thread.sleep(GATE_DELAY_MS)` 再改写呈现**——把呈现推到应用的输入法切换完成之后。
  释放帧不经过该分支（成对性不变，无粘键路径）；未声明能力/`Thread.sleep` 不可用/
  任何异常 ⇒ 不延迟（行为与现状一致，fail-open，仅计数）。
- `GATE_DELAY_MS` 初值 **150ms**（切换实测 53ms，留 ~2.8x 余量）；**真机数据后定稿**。

## 被否掉的方案（记录，避免重走）

1. **「切换完成后补发一次重按」**：报告层只能改写设备发来的帧（一次按下/一次释放各一帧，
   按住期间无帧），agent 无法凭空造输入事件；SendInput 重按会被豆包的 LL 钩子按
   `LLKHF_INJECTED` 丢弃（2026-09-04 四层结论）。**不可实现**。
2. **「agent 在按下帧处等待应用的放行信号（socket 通道）」**：Frida 的 JS 回调在单一
   JS 线程上串行化；在钩子回调里阻塞等待期间，socket 数据回调**无法被处理**，
   放行信号永远到不了等待循环。自适应当前需要「同线程可同步读取」的旁路（如文件轮询），
   复杂度与未知项（WUDFHost 的账号/ACL、File API 同步语义）本迭代不引入；
   先用固定有界延迟，后续若延迟成本显著再评估升级。

## 验证

- **agent 逻辑台**（`agent_logic_test.mjs`，无需 frida/提权/遥控器）：gate 默认关 → 不延迟、
  替换照常；gate 开 → 改写前**恰好睡一次 `delay_ms`** 且替换仍生效；释放帧不延迟；
  observe 模式/租约过期不延迟。阳性对照：对未含门内延迟的旧 agent 跑本组必须失败。
- **助手单测**：`W` 行解析（且拒绝 `W 2`/缺值/`S 00E6` 混入）、`gate` 命令线格式与令牌、
  drain 把 `W 1` 落成开关状态、断开回落关闭。
- **应用侧单测**：`W 1` 行编码（与助手解析逐字符对齐）。
- **真机复测 deferred**：装含本提交的包后，在「活动输入法非豆包」状态下按第一下——
  预期语音条直接出现；日志出现 `synth:gate delay_ms=150`，且 `ime_activation elapsed_ms`
  证明切换先于呈现完成；同时观察常按的额外延迟是否可接受（决定 150ms 是否需要调小）。
