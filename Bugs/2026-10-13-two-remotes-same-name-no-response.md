# 两支遥控器在 Windows 里同名：按错一支时界面毫无反应（②步按键行不亮）

- 发现日期：2026-10-13（Andy 真机截图 + 本机诊断日志；本机现场）
- 状态：已修复（自动化 passed；真机复核 `deferred`）
- 影响范围：0.8.6 起、本机两支遥控器（同为 RC 系列的 `…D9DB` / `…B76B`）同时配对时；
  Raw Input 侧"按「应用正在用的那支」过滤"（#249）之后表现最明显
- 功能点：Onboarding 第②步的按键检测 + Raw Input 路径过滤 + 连接后名称显示

## 现象与时间线（本机日志，UTC）

- `10:12:39` 用户进入②步；`10:13:05` 重新订阅按键边沿（`button_observation passed`）。
- `10:13:23` Raw Input 监听器启动：`matched_device_count=1`，绑定 `…c05d39c2d9db…`。
- `10:13:30` `stale_remote_event first_seen … bound_path=…c05d39c2d9db… event_path=…e85540b1b76b…`
  —— 另一支在发按键，按"非目标"丢弃。
- `10:13:45` 用户点设备行「连接」：`remote_target action=published` +
  **`ble_switch action=disconnect_previous terminal_result=passed`**（换机先断开旧的那支，本轮新逻辑）
  → 连上另一支（目标文件 `rc003-target.ini` 写入 `…e85540b1b76b`）。
- `10:13:53` 绑定审计按目标地址改绑到 `…e85540b1b76b…`（`action=rebound kept_previous=false`）。
- 用户"两支都按了"：`10:14:23` 起心跳仍为 `remote.button_not_ready detail=obs_0_n2`，
  整段没有 `map_edges`、`semantic_edges` 不涨。

## 根因

1. **两支遥控器的 Windows 名字完全相同**（截图里两行都叫「小米蓝牙语音遥控器」，没有 2 / 2 Pro），
   用户无法判断该点哪一行；他连上的那支（`…B76B`）不是手里按的那支（`…D9DB`）。
2. #249 之后按键按「应用正在用的那支」过滤是**有意的**（避免按住 A、程序响应 B），
   但被过滤掉的报文只进 `stale_remote_event_count`、界面上**没有任何解释** ⇒ 用户看到的就是
   "两条遥控器都按了，都没反应"。
3. 顺带暴露的一个 Raw Input 脆弱点：同一支遥控器的 HID 接口换过实例后，旧实例可能仍留在枚举里，
   绑定审计因此不重绑，而报文从新实例到达 —— 这类"同地址、不同实例路径"的报文此前同样被丢。

## 修复

- **② 步显示具体型号**（`RemoteStep.vue`）：已连接那一行的标题、以及下方「… · 已连接」一行，
  优先显示运行时按 GATT 读回的型号（小米蓝牙语音遥控器 2 / 2 Pro），型号未知才退回系统名字。
- **按到另一支时给一句解释**（`OnboardingPage.vue` + `RemoteStep.vue`）：等待本步普通按键期间，
  Raw Input 的 `stale_remote_event_count` **在本步内增长** = 另一支在发按键 ⇒ 就地提示
  「刚收到的是另一支遥控器的按键。当前连接的是「…」。请按这一支的普通按键；要用另一支，
  就点它那一行的「连接」。」（未连接时提示"先点一行「连接」选中你手上这一支"）；
  整步只提示一次，并落日志 `reportStepAction("remote", "other_remote_button", "passed")`。
- **同地址的其他实例路径也接受**（`raw_input_windows.rs`）：报文路径等于绑定路径，**或**属于
  当前目标地址（`remote_target::matches_address`）即处理；首次走这条兜底路径记一条
  `raw_input target_path_accept first_seen path_matches_bound=false`（无设备身份）。

## 第二轮（同日晚，Andy 抓到反例）

- **现象**：应用连的是「2 Pro」，按「2」（另一支）**却让②步通过**了。
- **根因**：报文接受判据里"报文路径 == 绑定路径"这一支没有与当前目标对照——绑定若停在另一支上
  （启动时按枚举顺序先绑了一路，或换机后审计还没重绑），那一支的报文就被当成本机按键。
  反向也成立：目标那一支若不在绑定上，它的按键反而被丢（此前"连 2、按 2 没反应"的一种解释）。
- **修复**：新增纯逻辑 `raw_input::report_path_accepted(bound, target, path)`——有目标时**只认目标
  地址**（绑定路径与同地址的其他实例都算），无目标时沿用旧行为（只认绑定路径）；报文处理改用它。
  单测覆盖四种组合（含"绑定停在另一支上"）。同轮把"多候选判监听器启动失败"改为挑一路先听
  （启动不再出现 10 秒一次的重试与按键空窗）。
- 隐私不变：仍不落任何设备身份，判据只在内存里比对。

## 第三轮（同日晚，Andy 复测第九轮后）

- **现象**：连甲支、按甲支通过了；**换连乙支后②步仍显示「已收到遥控器按键」**，不按一下也能继续。
- **根因**：`remoteButtonObserved` 是整步粘滞的布尔值——收到过任何一支的按键就置真，换连之后没有重置。
- **修复**：跟踪"已连接那一支的稳定身份"（运行时快照设备令牌优先、退回本会话连接成功的 id），
  身份**从一支具体遥控器换成另一支具体遥控器**时清掉观察状态与门禁（日志
  `button_observation_reset detail=remote_switched`）。瞬时清空（切换先断开上一支）不算换机；
  从未连接 → 首次连接不清（保留"按键已收到。还差一步：连接"的既有流程）。
- 测试先红后绿：`换连另一支遥控器后要重新按一下（之前那支收到的按键不算数）`。

## 第四轮（同日晚，Andy 截图：②步下方写「已连接」、上面两行都没标出来）

- **现象**：应用启动后直接进②步，连接是**启动恢复**的：下方信息行写着「小米蓝牙语音遥控器 2 · 已连接」，
  上面两行设备却都是普通「连接」按钮，认不出连的是哪一支。
- **根因**：设备令牌 `device_token(id)` 只对**整串 id** 做哈希——扫描返回的 id 与启动恢复保存的 id
  形态可能不同（前后缀/分隔符差异），同一支遥控器算出两个令牌 ⇒ 行与连接状态对不上。
  另外令牌只在连接握手的中途赋值一次，此前/此后任何一次快照重建（恢复、每次尝试、睡眠唤醒）
  都不带它，掉一次就再也回不来。
- **修复**：① 令牌改由**蓝牙地址**派生（`device_token` 内做地址解析，解析不出退回整串；
  单测覆盖两种 id 形态、大小写、以及"同一支必须同一令牌"）；② 在恢复、每次连接尝试、
  睡眠/唤醒重建快照时都带上令牌；③ 新增 `ble_identity action=ready token_present=…` 日志
  （只记布尔，不记身份）——下次这类问题一眼可断。
- 同轮修好 `runtime-simulation` 仿真构建（上一轮加字段时漏改仿真平台的两处字面量，特性构建编译不过）。

## 第五轮（同日晚，Andy 返工"没切换"）

- **现象**：向导里"系统输入法没有自动切换"，按语音键也没有兜底切换。
- **证据**（他本机 `1be64f3` 包的日志）：每次检查都到 `ime_activation … skipped_self_foreground`
  （前台是应用自己 ⇒ 按 2026-09-12 守卫跳过）；工具卡那条对齐则出现
  `ime_tool_select action=fired trigger=window_blur … still_self=true` 之后**再无任何尝试**。
- **根因两条**：① 向导窗在前台时守卫必然跳过（设计如此，防 WebView 整页重载）；
  ② 一次性布防在"失焦事件先到、前台仍是自己"时被 `take()` 取走后直接 return ⇒ 对齐永久丢失。
- **修复**：布防放回（`action=kept_pending reason=still_self`），下一次失焦再试；
  向导内的"直接切"做成**实验开关**（`%LOCALAPPDATA%\SayAll\ime-inline-switch.ini` 或
  `SAYALL_IME_INLINE_SWITCH=1`，日志 `ime_inline_switch enabled=true` /
  `ime_activation scope=wizard_inline`），Andy 已确认先装包试一次再决定保留或撤掉。
- 文案定稿：核对卡第一项「输入法切到“<工具名>”。」（仅微信 / 豆包）、麦克风一项补"语音输入设置"。
- **实验结论（2026-10-13 真机，同一晚）**：装了带开关的包、⑤步点输入框（前台是应用自己）——
  **输入法切得过去、页面没有闪/没有重载、按语音键后文字正常进输入框**。
  据此把"向导内直接切"从实验路径收成**正式路径**（删掉开关与 `ensure_ime_for_tool_inline`，
  `ensure_ime_for_tool` 直接走允许自身窗口前台的分支，scope 仍记 `wizard_inline`）。
  生产路径（按下语音键 / 工具选择）的守卫**保持不变**——本次只验证了向导这条检查路径。
- **当晚最终决定（Andy）**：不要向导里的自动切换，**只保留文字提醒** ⇒ ⑤步的输入法处理改为
  纯只读检查（`get_ime_status`）+ 说明卡；删掉 `ensure_voice_tool_ime` 命令、
  `ensure_ime_for_tool` 与 `ImeSwitchScope::WizardInline`。生产路径（按下语音键的兜底切换、
  工具选择的立即切换/布防）与主页面工具卡行为不变。
