# RC001 共享宿主：其它设备的报告字节被当成"电源"按键，游戏中被反复拉起"打开抖音"宏

- 发现日期：2026-11-25（客户反馈 22:03，本地 UTC+8；日志覆盖 16:43–21:27）
- 状态：**调查完成；已加入"来源画像"诊断（只读、不改判定），等待现场日志判定三条线索**
- 影响范围：1.9.7（`98fd2a2…`）、RC001（`ble_model model=Rc001`，界面显示"小米蓝牙语音遥控器 2"）、
  增强捕获助手 `rc003-helper`、共享 WUDFHost（`members=5 rc003_members=1`）
- 功能点：按键页「全按键支持」→ `rc003_bridge` 目标集下发 → 报告层按 usage 上报边沿 → 按键映射
  （`Power` 单击 = `run_macro`：打开 Chrome + 打开网址）
- 现象：用户打游戏期间**全程未碰遥控器**，每隔 10–20 分钟自动执行一次"电源 → 打开抖音"，
  前台从游戏直接跳到浏览器；当晚共 3 次
- 正常预期：物理未按下时，任何按键映射都不应执行
- 复现条件：同一 `WUDFHost.exe` 同时承载 RC001 与另一台**持续上报**的 BLE HID 设备
  （本次约 123.5 份/秒，≈8 ms 周期）；「全按键支持」开启；电源键配置了映射

## 证据（客户诊断日志，本地时间 UTC+8）

### 1. 20:45:39 起，同一宿主里出现一路 123.5 份/秒的报告流，遥控器自身几乎不动

- 助手心跳 `reports_seen`：20:33–20:45:09 恒为 130（4 小时累计 48 份）；
  20:45:39 的 30 s 窗口 +2258，此后稳定 **123.4–123.8 份/秒**，一直持续到日志结束
  21:27:12（`reports_seen=310455`）。
- 同期主程序 Raw Input（只绑遥控器设备路径）`raw_event_count`：
  20:31:28 = 350 → 21:26:11 = 376（**55 分钟只多 26 份**）。
- 21:26:11–21:27:01 三次语音会话期间 `activeSource` 属于遥控器，
  助手把同一股流计为异源：`foreign_reports` 625 → 4254（**+3629 / 约 29 s ≈ 125 份/秒**）。

结论：这股流**不是遥控器**，而是同一宿主里的另一台设备（会话期间被来源隔离判定为异源）。

### 2. 报告层当晚接管了 8 个 usage，包含电源与返回

  （视频里按键页显示「电源 · 单击 · 打开抖音」，「全按键支持」开启）。
- `0x00F1` 正是 Windows 键盘映射表里没有、所以返回键原生零事件的 usage；
  正常键盘不会输出它，说明这些值来自别的设备报告里的**数据字节**。

### 4. 命中后不仅误报，还改写了对方的报告

`target_hits` 与 `clears_ok` 逐次同步增长（35→59 时 56→80；59→64 时 80→85），
说明报告层把命中的两个字节清零后又回写——同一帧里对方设备的输入也被改掉。

## 根因

1. 报告层（`hardware/RC003/helper/agent/rc003_agent.js`）按**报告形状 + 内容**认键：
   `IoControlCode 0x80018483`、入参 8 字节、`out[0]==0x01`、偏移 3/5/7 的两个字节组成 u16
   且落在目标 usage 集合内，就算"遥控器按键"。
2. 该判据不认设备。共享宿主里 `NtQueryObject` 拿到的来源名是宿主自己的
   `\Device\UmdfCtrlDev-{GUID}`（同一宿主所有成员共用），2026-11-12 的来源隔离在这里
   退化为恒等；`activeSource` 又只在"报告里含目标 usage"时认领，空闲时任何来源都能抢先认领。
3. 于是另一台设备（本次为 8 ms 周期持续上报）的**任意数据字节**只要恰好等于
   `0x28/0x35/0x4A/0x4F–0x52/0x65/0x66/0x7F–0x81/0xF1`，就会被当成遥控器按下；
   命中 `0x0066` 时直接触发「电源 → 打开抖音」宏。
4. 这是 2026-11-18 已登记问题的扩展：当时只证实了键盘方向/OK 同 usage；
   2026-11-25 的修复（`7c439d5`）只在"共享宿主 + 键盘类成员"时让出方向 / OK / Enter，
   **电源 / 返回 / 音量± 仍在目标集**；客户使用的 1.9.7 不包含该修复，等于毫无防护。

## 边界与未知

- 具体是哪台设备（蓝牙鼠标 / 键盘 / 手柄）**未知**：日志不含设备身份，只有报告速率与
  来源隔离结论；需要用户逐个断开同连设备复测，或补"来源画像"诊断后才能定。
- 8 ms 周期 + 命中值（含 `0xF1`）更像指针/轴类数据；`0x0080/0x0081/0x007F` 也正好是
  有符号 8 位轴值 −128/−127/+127，但这只是推断，未取证。
- 遥控器自身的报告速率（按住时）未知；任何"按速率/按住时长过滤"的方案都必须先测。

## 下一步：来源画像采样（2026-11-25 已实现，只诊断）

`rc003_agent.js` 新增 `diag:` 行（`AGENT_BUILD = 2026-11-25.source-diagnostics`）：
**只读元数据、不改任何判定/清键/边沿**，经助手转成 `[AGENT] msg=diag:...` 进诊断日志。

| 行 | 字段 | 回答哪条线索 |
| --- | --- | --- |
| `diag:src_new` | `id` `h`（句柄）`nm`（对象名哈希）`nm_shared_with` `ob` | ① 同一对象名下是否有不同句柄 |
| `diag:src`（5 s/来源） | `n` `rate` `len`（Information 直方图）`st` `in`（8 字节请求头）`in_n` `in_chg` `edges` | ② 请求头是否每来源常量 ③ 长度是否每来源常量 |
| `diag:edge` | `src` `u` `len` `st` `in` | 把每条幽灵边沿绑到来源与长度 |
| `diag:src_closed` | `id` `n` `len` `in_chg` `edges` | 句柄关闭换代 |
| `synth:frame seen`（原有行） | 新增 `src` | 用户按语音键时，`src` 指向的就是**遥控器**；用它给上面各来源帖标签 |

判读：

- 先按语音键 3 次：`synth:frame seen ... src=N` 的 `N` 就是遥控器来源，其余 id 是别的设备；
- `h=` 不同、`nm=` 相同 ⇒ 可用句柄做来源键；
- 某来源 `in_chg=0` 且不同来源 `in=` 不同 ⇒ 请求头里带设备标识；
- 某来源 `len=` 只有一种取值且与其它来源不同 ⇒ 可用完成长度筛设备；
- 三者都不成立 ⇒ 只能回到按宿主取舍（A/B）。

采样步骤（真机）：

1. 装含本诊断的包后**重启电脑**：共享宿主的旧 agent 不会自动换到新代次
   （`[AGENT-STALE]` + shared 换代只重扫设备节点）。判据是日志出现
   `[AGENT] msg=agent:load build=2026-11-25.source-diagnostics`。
2. 遥控器 + 蓝牙键鼠保持同连：先按遥控器**语音键 3 次**（给遥控器来源打标签）→
   静止 10 s → 只动鼠标 10 s → 只敲键盘 10 s → 遥控器方向 / OK / 返回 / 音量± / 电源各按 3 次。
3. 取诊断日志，按时间切段对照 `diag:src` 的 `rate / len / in`。
4. 若复现幽灵动作，`diag:edge` 的 `src` 直接对上第 3 步的某一段。

## 修复选项（待拍板）

- **A（推荐）**：共享宿主 ⇒ 报告层目标集为空；方向 / OK / Enter 等回落 Raw Input + `key_gate`，
  返回 / 音量± / 电源的映射在该环境不可用（UI 说明原因）。彻底消除误触发与他设备改写。
- **B**：共享宿主里只让出 `0x0066` / `0x00F1`；音量± / 主页 / TV / Menu 仍可能被幽灵触发。
- **C**：先不动行为，给 agent 加"来源画像"诊断（实际报告长度、来源哈希、每秒速率、命中槽位），
  下次复现后按设备类别做真正可区分的判据。
- 可选加固：`run_macro` 类动作要求按住 ≥40 ms（本次幽灵 7–30 ms，真人 ≥50 ms），
  只影响宏，不影响快捷键/方向映射的即时性。
