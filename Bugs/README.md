# Windows Bug 记录规范

## 固定流程

非简单 Bug 必须按以下顺序处理：

1. 记录可重复触发条件、实际错误和正常边界；
2. 先查看对应时间段的结构化日志，区分最终结果与中间事件；
3. 根据复现和日志缩小代码范围，明确根因假设并用最小实验验证；
4. 只修复已确认根因；
5. 重新执行原始复现并覆盖受影响的稳定基线。

模拟硬件、单元测试、构建和安装器检查只能证明各自边界；没有真实 Windows、RC001/RC003 或第三方工具时，状态必须写为 `deferred`。

## 记录模板

每个 Bug 使用 `YYYY-MM-DD-short-name.md`，至少包含：

```markdown
# 标题

- 发现日期：
- 状态：调查中 / 已修复 / 等待真机验证 / 已归档
- 影响范围：版本、Windows 版本、RC001/RC003、第三方工具
- 功能点：模块或用户功能
- 现象：一句话描述错误行为
- 复现条件：
- 正常预期：
- 证据：日志时间段、命令、提交或测试手册
- 根因：已确认事实与仍未知边界
- 修复：最小改动及文件
- 验证：命令、观察结果和 `passed|failed|deferred`
- 隐私检查：确认未包含个人路径、设备身份、语音内容或凭据
```

历史资料不足时明确写“未知”，不得用推测补齐证据。Bug 文档和日志附件均须脱敏。
