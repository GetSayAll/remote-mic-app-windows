# 语音键 F5 抑制器「链头 bump」去留实测手册

## 测试对象

- **判定目标**：`crates/sayall-windows/src/key_suppressor.rs` 的"会话开始 + 每 10 秒"钩子重装
  （`bump_to_chain_head`，见该文件 `:290` 定时器、`:297-299` 消息分支、`:410` 会话开始投递）
  在实际使用中是否仍有保留价值；移除后 F5 抑制是否出现任何回归。
- **基线组**：当前 `main` 构建（含 bump）。
- **候选组**：同一提交上**仅**移除"会话开始 + 10s 定时"两处 bump、保留启动时一次安装的实验构建
  （实验分支，不合并；探索性改动不要求先写测试）。
- **适用环境**：Windows 10 1809+ / Windows 11 x64；微信输入法为会话活动输入法；RC001 与 RC003
  **各自单独记录**，任一型号缺环境即记 `deferred`，不得用仿真或单元测试代替。
- **关联材料**：`docs/investigations/2026-09-27-ll-hook-chain-order-fifo.md`（FIFO 实证，处置待定）、
  `Bugs/2026-09-04-wetype-zero-gap-injection.md`（bump 的原始引入理由）、
  `Bugs/2026-09-27-capture-preheld-keys-block-recording.md`（`hWnd=NULL` 定时器 id 缺陷）、
  issue #111（报障人指出的"常驻钩子 + 10s 重装 + 回调内 60ms 等待"三条指控）。

## 测试目标

用真机判定：把 `key_suppressor` 的定期/session 重装移除后，遥控器语音键 F5 是否**在所有已登记
场景下仍然被完整吞下**（`seen == swallowed`、`leaked=0`），且语音端到端不受影响；从而给
"移除 / 保留"（或"按场景拆分"）一个可引用的实测结论，替代当前凭推理悬置的状态。

## 背景（为什么现在必须测）

- 2026-09-04 引入 bump 的理由是"微信输入法等目标若在本应用之后安装 LL 钩子，重装能保证本抑制器
  先看到遥控器 F5"。该前提在 2026-09-27 被本机实验推翻：**LL 钩子链是 FIFO（先安装先调用），
  重装只会把本钩子推向链尾**（`cargo run --example hook_order_probe -p sayall-windows`）。
- 但同日只落了 `key_gate` 侧；FIFO 文档对 `key_suppressor` 明写"移除或保留**需以 F5 实测为准**"，
  至今未执行。同一份文档给的旁证是"F5 不是输入法和弦键，输入法放行后本钩子无论链位都能拿到"，
  属于推理而非实测。
- 2026-09-27 修掉 `hWnd=NULL` 线程定时器忽略传入 `nIDEvent` 的缺陷后，这个 10 秒重装从
  **静默失效**变成**真的会执行**（0.3.0 起）。因此"它一直没生效也相安无事"不能作为删除依据，
  反而正是必须实测的原因：现在的行为与历史现场不同了。
- F5 抑制的已知失败模式（判定时必须能观察到）：F5 泄漏进焦点应用（记事本收到时间戳/功能键）、
  或泄漏进微信输入法导致注入和弦被判"额外按键"而拒绝（`Bugs/2026-09-04-wetype-zero-gap-injection.md`）。

## 安装前准备

1. 记录 Windows 版本、微信输入法版本、遥控器型号、SayAll 版本（两组各自记录）与两次构建的
   精确 commit。
2. 两组包都用本地测试包（NSIS 或 `target/release` 构建），记录 SHA-256；不要用任务管理器强杀
   正在连接的实例，部署前先走应用自身"退出"（见 `AGENTS.md` 运维与自愈节）。
3. 准备一个记事本窗口作为"F5 泄漏"阳性对照：任一时刻若 F5 泄漏进系统，会直接可见。
4. 确认微信输入法的语音快捷键与 SayAll"按住说话快捷键"一致，且微信输入法为会话活动输入法。
5. **观测缺口必须先补齐**：当前 `key_suppressor` 没有任何 bump 计数（`key_gate` 有
   `HOOK_BUMPS_OK/FAILED`，见 `key_gate.rs:332-333`）。实验分支应在 `suppressor_stats` 一行里
   补 `bumps_ok=` / `bumps_failed=` 两个累计数——否则基线组"10s 重装确实发生"无法证明，
   "移除有没有代价"就无从判定（这一对计数也顺带给 issue #111 类报障提供归因证据）。
   计数器只允许原子递增，不得在钩子线程内做 IO。

## 观测点（每次会话都能读到）

默认诊断日志 `%LOCALAPPDATA%\SayAll\Logs\sayall-diagnostic.log`，每次语音会话开始会落一行
快照（`key_suppressor.rs:398-406`）：

```text
suppressor_stats seen=<n> swallowed=<n> leaked=<n> waited_late=<n> raw_remote_f5=<n> link_guard=<bool> bumps_ok=<n> bumps_failed=<n>
```

- 判据一：`seen == swallowed` 且 `leaked=0`（增量口径：本次会话相对上次的差值）。
- 判据二：同会话链路完整 —— `chord_press result=ok` → `audio_stream phase=started` →
  `audio_session finish`；且不出现 `wetype_revive result=...` / `chord_retry result=ok`。
- 判据三：焦点应用（记事本）**不出现** F5 的时间戳插入或功能键动作；微信输入法不出现
  "额外按键"类拒绝（表现为本次按住整段无听写）。
- 判据四（仅基线组）：`bumps_ok` 在跨越 ≥30 个 10s 周期的闲置后确实增长，证明重装真的在执行。
- `voice_f5_guard active=...` 用于确认 BLE 链路转换期的守卫状态符合预期。

## 用例矩阵（两组各跑一遍，逐条记录）

| 编号 | 用例 | 次数 | 备注 |
|---|---|---|---|
| E1 | 冷启动首按：冷启动应用 → 连接遥控器 → 首次按住说话 3–5s | 5 | 必须包含一次"应用先启动、遥控器后连接" |
| E2 | 闲置首用：连接就绪后闲置 ≥5 分钟（跨过 ≥30 个 10s 周期）→ 首次按住 15s | 3 | 与"延迟优化必须保证冷态首用"规则同一判据 |
| E3a | 先启动 SayAll、后启动/唤醒微信输入法（IME 钩子晚于本钩子）→ 按住说话 | 2 | 不得为制造场景编辑 WeType 私有配置 |
| E3b | 先有微信输入法、后启动 SayAll（IME 钩子早于本钩子）→ 按住说话 | 2 | 与 E3a 互为对照，覆盖两种链序 |
| E3c | 会话期间切换输入焦点/输入法（触发 IME 钩子重建）→ 再按住说话 | 2 | 对应 FIFO 文档推论 3 的"钩子休眠/唤醒"形态 |
| E4 | 睡眠恢复：Windows 睡眠 → 唤醒 → 不做其它操作直接首次按住 15s | 2 | 覆盖唤醒后钩子/链路重建 |
| E5 | 快速连按：连续 20 次 ~1s 会话，随后 3 次 10–15s 长按 | 1 轮 | 同时验证 F5 边沿配对（DOWN 泄漏则 UP 必放行）无粘键 |
| E6 | 断连重连首按：会话期间断开遥控器（关闭或移出范围）→ 重连 → 首次按住 | 2 | 验证无残留按住、无跨会话泄漏 |
| E7 | 外部钩子共存（只记录不判定）：机器上其它常驻 LL 钩子软件在场时跑 E1 | 1 | 记录软件清单，用于解释例外 |

## 判定标准

- **可移除**：候选组（无 bump）在 E1–E6 的所有场景下，`seen == swallowed`、`leaked=0`、
  端到端语音与基线组无差异；同时基线组 `bumps_ok` 确有增长（证明差异确实来自该逻辑）。
  结论落地方式：删除"会话开始 + 10s 定时"两处 bump（保留启动时一次安装与 60ms 有界等待、
  边沿配对），同步 `key_suppressor` 注释与本手册结论，并在 `TODO.md` 标完成。
- **保留**：候选组出现任意一次 `leaked>0`、或者 F5 到达记事本/微信输入法导致听写失败
  ⇒ 结论为保留，并归档触发场景（哪个用例、哪一组、时间点、日志行），说明 FIFO 推理在
  该形态下不成立（例如 IME 钩子在会话中重建的边沿）。
- **按场景拆分**：只有部分用例出现差异时，逐场景给结论，禁止把单场景结论推广成整体结论。

## 边界

- 自动化、仿真与单元测试**不能**代替本手册任一用例：钩子链序与输入法行为都是进程外的真实时序。
- 本次判定**不包含**：60ms 有界等待的去留、边沿配对规则、`raw_remote_f5` 归因通道；
  这些是独立决策，不得顺带改动。
- 若实验期间微信输入法发生版本变化，结果记录必须写明版本（当前取证版本为 2.1.4.6），
  不同版本的钩子行为不可混用同一组结论。
- 结果文档与日志必须脱敏：不得包含蓝牙地址、HID 实例路径、设备身份、语音内容或个人路径。
- 未跑完的型号、场景一律记 `deferred`，不得以另一型号或另一版本的结果代替。
