# Windows「聚焦输入框」验收

本手册覆盖按键动作「聚焦输入框」与「打开应用」的三种聚焦方式（只打开应用 /
用应用快捷键聚焦 / 聚焦已记录的输入框）。步骤是验收方法，不代表所有场景均已通过。

实现边界（先读，避免把预期错当成缺陷）：

- 只用公开 UI Automation 读控件语义（类型 / AutomationId / ClassName / 是否可聚焦 /
  是否只读 / 是否密码框 / 相对位置），**不读输入内容**，不做进程注入，不需要管理员权限；
- 学习输入框只记录控件特征（`controlType` / `automationId` / `className` / `name` /
  相对矩形），其中 `name` 与窗口标题属本地配置数据，只写本机配置文件，不进日志、不随诊断上传；
- 目标应用以管理员身份运行时读不到界面（UIPI）：按 `not_accessible` 失败并提示，不要求用户提权；
- 不提供「无 UIA 树应用」的位置点击兜底（决策点 D1/D2 未启用）。


探针只打印类型 / 长度 / 哈希 / 几何，用于取证，不读也不打印任何输入内容。

## 桌面验收（普通权限，人工参与）

1. **动作可用**：按键页任一按键的任一触发方式选「聚焦输入框」，保存后按住该键——
   焦点应落到当前前台应用的可编辑输入框；不切换应用、不注入文字。
2. **一次手势一次执行**：按住不放不得重复聚焦；未配置双击/长按时按下沿即执行；
   配置了双击时，单击等双击窗口结束才执行（双击不误触聚焦）。
3. **已在用的输入框不被抢走**：焦点已在某输入框时触发，应保持在该输入框。
4. **失败路径**（每种都应有可解释提示与日志）：前台是本应用自己（跳过，非错误）、
   目标无可用输入框、目标不是前台、目标已退出、目标不可读（管理员权限）、总预算超时。
5. **打开应用 + 聚焦**：三种聚焦方式分别验证——只打开；用应用快捷键聚焦（录入组合后
   打开应用并注入该组合）；聚焦已记录的输入框（先「开始学习输入框」，3 秒内点目标输入框，
   之后再打开该应用应回到该输入框）。
6. **学习边界**：学习窗口内点到按钮 / 只读网页根 / 密码框不得记为可用输入框（应提示失败）；
   点本应用自己的窗口不记；3 秒内没有稳定命中应给失败提示而不是静默成功。
7. **资源与生命周期**：连按、按住不放、目标中途退出、断连、睡眠唤醒后首次触发、
   应用退出（聚焦服务线程有界退出）均不得残留状态或卡住按键线程。

## 已实测（自动化/探针，非完整验收）

- 候选扫描与聚焦读回：Chrome fixture（搜索框 + composer）、DimAgent（TipTap `Group`）、
  记事本（`Document`）；焦点迁移用独立读回的元素身份哈希确认，`attempts=1`、`elapsed_ms≈90–120`。
- 学习：Chrome fixture 搜索框，`learned control_type=Edit id_chars=10 elapsed_ms=107`。
- 候选门槛：Chromium 只读网页根（`Document` + `IsReadOnly=true`）被拒绝。
- 失败路径：UIA 不可达/无树应用立即失败（不做长重试）。
