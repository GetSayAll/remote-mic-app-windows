# Windows「聚焦输入框」验收

本手册覆盖按键动作「聚焦输入框」与「打开应用」的聚焦方式：预设（默认）应用打开后
使用产品默认聚焦方式（Chrome / 网易云快捷键，其余自动选择输入框）；所有打开应用目标
都显示「聚焦方式」面板，可选只打开 APP / 自动选择输入框 / 使用 APP 快捷键聚焦 /
聚焦已记录的输入框 / 记录点击位置。组合动作的「聚焦学习过的输入框」步骤只读复用
按键页的目标与聚焦方式。步骤是验收方法，不代表所有场景均已通过。

实现边界（先读，避免把预期错当成缺陷）：

- 只用公开 UI Automation 读控件语义（类型 / AutomationId / ClassName / 是否可聚焦 /
  是否只读 / 是否密码框 / 相对位置），**不读输入内容**，不做进程注入，不需要管理员权限；
- 学习输入框只记录控件特征（`controlType` / `automationId` / `className` / `name` /
  相对矩形），其中 `name` 与窗口标题属本地配置数据，只写本机配置文件，不进日志、不随诊断上传；
- 目标应用以管理员身份运行时读不到界面（UIPI）：按 `not_accessible` 失败并提示，不要求用户提权；
- 无 UIA 树的应用可用「记录点击位置」兜底（记录相对坐标；窗口尺寸变化超过 25% 时
  拒绝点击）。

## 桌面验收（普通权限，人工参与）

1. **动作可用**：按键页任一按键的任一触发方式选「聚焦输入框」，保存后按住该键——
   焦点应落到当前前台应用的可编辑输入框；不切换应用、不注入文字。
2. **一次手势一次执行**：按住不放不得重复聚焦；未配置双击/长按时按下沿即执行；
   配置了双击时，单击等双击窗口结束才执行（双击不误触聚焦）。
3. **已在用的输入框不被抢走**：焦点已在某输入框时触发，应保持在该输入框。
4. **失败路径**（每种都应有可解释提示与日志）：前台是本应用自己（跳过，非错误）、
   目标无可用输入框、目标不是前台、目标已退出、目标不可读（管理员权限）、总预算超时。
5. **打开应用 + 聚焦**：
   - **预设应用默认聚焦**：在「打开应用」分组点任一预设（卡片文字以“打开”开头，
     如“打开记事本”“打开 Chrome 浏览器”），下方「聚焦方式」应默认选中该应用实际
     使用的策略：Chrome / 网易云为“使用 APP 快捷键聚焦”，其余预设为“自动选择输入框”。
     绑定并按下该键后，应用打开或切到前台，焦点应落在它最合适的输入框。Chrome 应聚焦
     地址栏；网易云音乐应打开搜索页、聚焦搜索框并全选旧查询（此时输入任意文字应替换
     旧内容）。无输入框的应用（如计算器）只打开，不误报失败。
   - **手动改选与恢复默认**：选择其他策略后保存，再选中该预设应保持用户选择；点
     “恢复默认”后应回到产品默认策略。自定义应用没有显式档案时默认“只打开 APP”。
   - **面板形态**：标题“聚焦方式”与“打开应用”等分组标题同字号、同字重；策略选项
     沿用基础按键 / 打开应用的 chip 风格，同一换行网格里依次是“只打开 APP”
     “自动选择输入框”“使用 APP 快捷键聚焦”“聚焦已记录的输入框”“记录点击位置”。
     快捷键档显示键盘图标与组合键只读 chip，旁边是“点击录入快捷键”和“清除”chip；
     输入框档显示“开始学习输入框”chip 与状态文字。面板与下方“组合动作”组的间距
     应与其他分组一致，不应出现“测试输入框”“测试打开与聚焦”入口。
   - **学习输入框**：点「开始学习输入框」→ 先打开/切换目标应用 → 显示
     “正在等待你点击目标输入框……”→ 在最多 6 秒内点击输入框 → 显示“输入框学习成功。”，
     之后打开该应用应回到该输入框。记录点击位置同样先打开目标应用，再把鼠标停在
     输入框上等待记录。
   - **组合动作与按键页同面板**：进入组合动作的“聚焦学习过的输入框”步骤，目标 App
     列出与按键页相同的全部应用（10 个预设 + 自定义应用，含“扫描本机应用 / 添加应用”），
     显示为“打开…”chip；下方“聚焦方式”是相同的五个 chip，默认选中该 App 的实际策略。
     快捷键档应能录入/清除，输入框档应能“开始学习输入框”，点位置档应能“开始记录位置”；
     操作与按键页一致。改选聚焦方式、学习或记录后应写回共用档案；在按键页学习过的
     输入框，回到组合动作页应显示“已记录目标输入框”，不需要重复学习；反向同样成立。
     两边都不提供“测试输入框 / 测试打开与聚焦”入口。
6. **学习记忆**：已学习过的输入框、点击位置和显式快捷键必须保留；升级到 schema 3
   只清掉旧 UI 留下的“自动选择 / 只打开”默认档案，不能要求用户重新学习。
7. **学习边界**：学习前目标应用应自动打开；打开失败应给“没能打开目标应用”提示。
   学习窗口内点到按钮 / 只读网页根 / 密码框不得记为可用输入框（应提示失败）；
   点本应用自己的窗口不记；最多 6 秒内没有稳定命中应给失败提示而不是静默成功。
8. **资源与生命周期**：连按、按住不放、目标中途退出、断连、睡眠唤醒后首次触发、
   应用退出（聚焦服务线程有界退出）均不得残留状态或卡住按键线程。

## 已实测（自动化/探针，非完整验收）

- 候选扫描与聚焦读回：Chrome fixture（搜索框 + composer）、DimAgent（TipTap `Group`）、
  记事本（`Document`）；焦点迁移用独立读回的元素身份哈希确认，`attempts=1`、`elapsed_ms≈90–120`。
- 学习：Chrome fixture 搜索框，`learned control_type=Edit id_chars=10 elapsed_ms=107`。
- 地址栏学习（2026-10-15）：Chrome omnibox（`Edit / OmniboxViewViews / 地址和搜索栏`）
  修复前 `learn_failed=NoCandidate`，修复后 `learned id_chars=9 class_chars=16 elapsed_ms=107`；
  自动选择路径仍然拒绝地址栏（学习档与自动档分离）。
- 位置点击（2026-10-15，面向无 UIA 树应用）：记事本记录 `x_ratio=0.5000 y_ratio=0.5961
  window=888x671`，点击阶段 `absolute=(2389,694)`、`click_submitted=ok`、
  `focused_after=Document/RichEditD2DPT`。
- 候选门槛：Chromium 只读网页根（`Document` + `IsReadOnly=true`）被拒绝。
- 失败路径：UIA 不可达/无树应用立即失败（不做长重试）。
- 聚焦方式面板 UI（2026-10-23）：浏览器预览 1200px 目视与组件测试均通过——五个策略
  chip（含“自动选择输入框”）同一换行网格、预设默认选中、快捷键只读 chip、输入框
  状态行，且已移除测试按钮；面板与“组合动作”组的间距为 12px，与其他分组一致。
  安装包 WebView2 内的目视与 UIA 取证见本地测试包目录下的截图。
- 组合动作聚焦步骤 UI（2026-10-23）：与按键页使用同一套完整面板——目标 App 列出
  全部预设 + 自定义应用（含“扫描本机应用 / 添加应用”），下方五个聚焦方式 chip 按
  实际策略选中；快捷键录入、输入框学习、点击位置记录、清除与恢复默认都在两侧可用，
  并写回同一份共用档案。浏览器预览证据见本地测试包目录 `combo-focus-step.png`
  （显示 10 个预设 chip、已学习输入框选中“聚焦已记录的输入框”、状态“已记录目标输入框”
  和“开始学习输入框”入口）；`focus-panel-preset-chrome.png` 为按键页对照。

探针（只读/低风险，见 `Testing/probe-uia-focus.ps1`）：

```powershell
# 记录点击位置 / 按记录位置点击（生产函数；坐标为相对窗口比例）
cargo run -p sayall-windows --example focus_probe -- --learn-point notepad
cargo run -p sayall-windows --example focus_probe -- --point-click notepad --x-ratio 0.5 --y-ratio 0.6 --window-width 888 --window-height 671

```
