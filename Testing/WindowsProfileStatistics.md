# 个人中心统计页测试手册（Windows）

适用版本：2026-10-24 起的个人中心改动；对齐 Mac `SettingsView.statisticsPage`。

## 测试前准备

1. 用本分支的本地测试包安装（不要用旧包；安装前先正常退出正在运行的安装版）。
2. 准备 RC001 与 RC003 各一支；两支分别完成一轮，不能互相替代。
3. 至少准备一个能接收语音输入的目标应用（如记事本、微信），并确认语音链路可用。
4. 打开应用，进入侧栏最底部「个人中心」；记录初始 KPI 与排行榜。

## 用例一：页面结构与入口

1. 观察侧栏：不显示版本号，也没有「分享」入口；个人中心固定在最底部。
2. 未登录时个人入口显示「个人中心」；登录会员账号后，只显示邮箱 `@` 前最多 10 个字符。
3. 个人中心图标应与托盘、窗口图标一致，并在设置页切换图标后同步变化。
4. 点击个人中心，页面标题为「个人中心」，右上为绿色「数据仅存本机」。
5. 确认「数据仅存本机」是状态文字，不是可点击按钮；样式与 Mac 状态胶囊一致。
6. 页面顶部、累计按键上方应显示「分享无线麦 SayAll」面板，默认收起。
7. 在默认窗口（约 1066×800）查看 4 个 KPI 是否单行、无截断。
8. 从页面顶部滚动到底部，再滚回顶部。

预期：

- 侧栏入口位置与文字正确；完整邮箱不出现在侧栏；没有版本号或分享入口。
- 应用 logo 与托盘图标同源；切换「默认 / 几何鸭」后两边一致。
- 分享面板位于累计按键上方，不改变页面路由。
- 4 个 KPI 单行；累计语音使用「33 分钟 12 秒」这类中文单位；左侧排行榜、右侧使用日历 + 单次语音排行。
- 日历 7 行完整可见；方格为正方形，宽度不足时可横向滚动。
- 页面底部语音排行最后一条与页面内详情完整可见，可滚回顶部。
- 不出现「回眸」「查看全部回眸」「少—多」图例。
- 浅色、深色下文字清晰，中文不小于 12px。

## 用例二：空数据

1. 在全新状态目录或卸载后重装的全新用户环境打开个人中心。

预期：

- 4 个 KPI 显示 0 / 0 秒。
- 两个排行榜与语音排行显示对应空文案。
- 日历显示最近半年浅灰格，不出现错误提示。

## 用例三：实体按键统计

1. 记录初始「累计按键次数」「本周按键」「实体按键排行」。
2. 在个人中心外按 5 次普通实体键（含返回、确定、方向）。
3. 返回个人中心。

预期：

- 累计按键次数至少 +5，本周按键 +5。
- 对应实体按键排行次数增加。
- 若该键的单击动作已配置且未禁用，「常用快捷键 / 动作」也增加。
- 动作榜只统计当前单击动作；修改映射后历史计数归到新动作。

## 用例四：语音统计

1. 记录初始「累计语音时长」「最长单次语音」「单次语音时长排行」。
2. 面向目标应用完成一次 2 秒以上语音输入，并确认文字进入目标应用。
3. 返回个人中心。

预期：

- 累计语音时长增加；最长单次语音按需更新。
- 语音排行出现一条：时长、应用名、结束时间。
- 微信应显示「微信」，不显示 `WeChat` / `Weixin`；其他预设使用产品名；未知程序显示去掉 `.exe` 的文件名，拿不到应用名时显示「未知应用」。
- 语音键本身计入累计按键次数，但不出现在「实体按键排行」。
- 排行最多 10 条；超出后只保留时长最长的 10 条。

## 用例五：重启与升级兼容

1. 记录当前 KPI 与排行。
2. 正常退出应用并重新启动。
3. 打开个人中心。
4. 用旧版本写下的 `settings.json`（含 `usage_statistics.days`、无新字段）启动一次，再打开个人中心。

预期：

- 重启后 KPI 与排行保留。
- 旧配置升级后旧累计统计保留；按控件计数与语音排行从新版本开始积累，不出现读取失败。
- 不出现数据重复累加（同一次操作只增加一次）。

## 用例六：断连、睡眠与异常收尾

1. 语音会话结束后立即断开遥控器。
2. 重新连接，再完成一次按键与语音。
3. 睡眠唤醒后重复一次。
4. 若可复现，强制结束应用后重启，检查最后一次统计是否丢失（允许最多 1 秒按键批量的边界）。

预期：

- 断连/睡眠不会产生重复语音记录，也不会把未结束会话写成超长记录。
- 重连后统计继续增长。
- 应用退出前的最后一次 flush 尽量保留；强制结束的场景按日志与设置文件判断，不把仿真结果当真实收尾。

## 用例七：持久化失败（可选，开发/诊断）

1. 将 `settings.json` 暂时设为不可写（或检查日志中注入的写失败）。
2. 按键并完成一次语音。

预期：

- 按键与语音功能不中断。
- 日志出现 `usage_stats action=flush ... terminal_result=failed ... retryable=true`；恢复可写后出现 `reason=recovered`。
- 页面仍显示上一次成功读取的数据，并给读取失败提示（如读取也失败）。

## 用例八：分享无线麦

1. 打开个人中心，确认页面顶部、累计按键上方有「分享无线麦 SayAll」面板且二维码默认收起。
2. 点击「显示二维码」，确认面板在原页面展开。
3. 手机扫码，核对打开的地址。
4. 点击「复制链接」，粘贴到记事本。
5. 点击「收起」，确认二维码从原页面移除。
6. 再次展开并重复复制，验证状态反馈不会卡死。

预期：

- 标题「分享无线麦 SayAll」，说明提到在 Windows 上进行语音输入。
- 二维码与链接都是 `https://sayall.app/?from=win_share`，扫码和复制内容一致。
- 二维码来自本机资源，不请求第三方二维码服务。
- 复制成功显示「链接已复制」；失败显示「链接复制失败」，不假装成功。
- 折叠/展开不跳转页面、不弹独立窗口；收起后「显示二维码」按钮保持可用。

## 自动化与证据

```powershell
corepack pnpm test
corepack pnpm build
cargo fmt --all -- --check
cargo test --workspace
cargo check -p sayall-windows-app --features runtime-simulation
scripts/test-windows-runtime-simulation.ps1   # 先构建 runtime-simulation
scripts/ci-preflight.ps1
```

页面走查：

- 浏览器预览尺寸：1066×800、1600×900；浅色/深色各一组。
- 检查侧栏无版本号或分享入口、应用 logo、页面顶部分享面板、KPI 单行、左右栏比例、日历方格、月份/星期标签、底部排行完整可见。
- runtime simulation 已加入个人中心导航、4 KPI、日历、内联分享展开/收起和侧栏无版本号断言。

边界：

- 自动化与浏览器预览不能替代 RC001 / RC003 真机验收。
- 应用显示名只来自前台可执行文件名映射，不读取窗口标题或完整路径。
- 本版本没有回眸页，因此不验证回眸跳转，也不应出现相关入口。

## 记录格式

每个型号记录：

- 型号：RC001 / RC003
- 包路径与 SHA-256
- 初始 KPI / 排行
- 按键与语音后的 KPI / 排行
- 重启、断连、睡眠后的结果
- 结论：passed / failed / deferred
- 失败时的日志时间窗与对应 `usage_stats` 行（不含应用名等隐私字段）
