# Windows 回眸原始录音：格式与生命周期决策

- 日期：2026-10-25（2026-10-26 更新：支持「仅录音」条目，manifest 记录应用身份）
- 范围：Windows「回眸」原始录音（保存、播放、导出、删除）
- 参考：Mac `RecordingAssetStore.swift` / `RecordingAssetCoordinator.swift` 的行为，不复制 Swift 源码
- 产品规范：[docs/product/reflections.md](../product/reflections.md)
- 真机用例：[Testing/WindowsReflections.md](../../Testing/WindowsReflections.md)

## 1. 结论

Windows 使用**未压缩 WAV（PCM s16le，16 kHz，单声道）**；录音仍由「保存原始录音」开关控制，但没有匹配文字记录时不再隐藏：

- 目录：`%LOCALAPPDATA%\SayAll\transcripts\v1\audio\<sessionId>\`
- 文件：`original.wav` + `manifest.json`
- manifest 记录会话号、起止时间、时长、字节数、格式、采样率、声道数、目标应用键与名称；不含窗口标题或文字。
- 录音开关默认关闭；只有「记录回眸」开启时可用。录音成功但文字捕获失败时，页面以「仅录音」分组展示。
- 页面只读 manifest；播放时才读取 WAV 并转成 data URL；导出复制到用户选择的路径；删除走 Windows 回收站。

## 2. 为什么不用 AAC / m4a

Mac 使用 AAC `.m4a`，因为 macOS 自带编码器与播放器。Windows 侧若照搬需要额外编码依赖、运行库或 ffmpeg 子进程，且当前语音链路已经是 16 kHz 单声道 PCM：

1. 直接写 WAV 不引入编码器、许可证或外部二进制，符合仓库“基础路径不依赖额外驱动/服务”的边界。
2. WebView2 原生支持 WAV 播放，不需要前端解码库。
3. 文件可以只追加 PCM 数据，结束时回填 44 字节 WAV 头；实现简单，失败点少。
4. 代价是文件更大：16 kHz × 2 字节 × 1 声道 ≈ 115 KB/s，10 分钟约 69 MB。当前单次语音通常几十秒，且页面只按会话读取；后续如体积成为问题，再评估有损编码。

没有沿用 Mac 的 AAC 容器，也没有复制其播放/导出实现。

## 3. 生命周期与失败边界

- `StreamStarted`：绑定会话号后同步启动录音 writer，保证第一帧 PCM 之前文件已打开。
- `handle_audio` 解码出的 PCM：先追加到录音队列，再送音频输出；录音队列是非阻塞 `try_send`，溢出时丢弃**整段**录音，不写半截 manifest。
- `StreamStopped`：结束 writer，回填 WAV 头，原子写 manifest；文字捕获继续按原流程结算。
- `StreamStopped` 丢失、新 `StreamStarted`、音频输出失败、和弦注入失败、关闭开关、应用退出：统一取消当前录音并删除未完成的 partial 目录。
- 目录/写入/manifest 失败只记录 `transcript_recording ... result=failed`，不影响语音、文字上屏和文字记录。
- 零采样或写入失败不生成 manifest；页面不会出现不可播放的空录音。

## 4. “仅录音”条目的决策（2026-10-26 修订）

Mac 的录音可以出现“没有文字、只有录音”的条目，并在页面上用单独分组展示。Windows 首版曾把录音收紧为文字记录的附属能力，导致 WorkBuddy、微信 4.x 等不暴露 UIA 文字的应用虽然成功写入 WAV，但录音在页面上不可见。用户明确要求对齐 Mac，因此改为：

- 录音仍在「记录回眸」+「保存原始录音」都开启时写入，文字捕获失败不影响录音收尾；
- 页面按 `sessionId` 把录音挂到文字记录；没有匹配文字记录的录音进入「仅录音」分组；
- 仅录音条目按目标应用和本机日期展示，支持播放、导出、删除；
- 录音开始时从当前前台应用读取应用身份（应用键与显示名）写入 manifest；微信的 `Weixin`/`WeChat` 显示名统一为「微信」，但稳定键仍用原始名，避免已有记录被拆成新应用；读取失败或旧 manifest 没有身份时归入「未知应用」，不影响播放；
- 图标缓存缺失时按显示名只读扫描当前进程，提取公开 Shell 图标并写入缓存；微信、WorkBuddy 等只有录音的应用不再回退成通用文档图标；
- 删除应用时同时删除该应用的文字记录、关联录音和仅录音条目；全部删除仍整体移入回收站；
- 录音成功落盘后发出只含会话号的 `transcript-recording-finished` 事件，页面静默刷新；没有文字记录时也能及时显示。

旧录音不会迁移或补写应用身份；它们在页面显示为「未知应用」，避免根据录音内容或路径猜测来源。录音仍不自动清理：文字捕获失败可能只是暂时读不到，录音可能是用户唯一可恢复的原始材料。

## 5. 隐私与存储

- 录音文件只存在本机，不自动上传；不写入语音文字、窗口标题、文档名、URL、设备地址或进程路径。
- 目录名只使用随机会话号；manifest 只记录目标应用键与显示名，不记录可执行文件路径。
- 页面快照只返回会话号、起止时间、时长、字节数、应用键与名称；不返回文件路径。
- 删除文字记录、删除当前应用、全部删除都走回收站；删除文字记录时关联录音一并删除；仅录音条目提供自己的删除入口。卸载不主动删除 `transcripts` 根目录。
- 日志只记录动作、结果、原因、时长、字节数，不记录文件路径、音频内容或窗口标题。

## 6. 验证

自动化覆盖：

- WAV 头、字节数、时长、manifest 校验；
- 关闭开关不写、取消清理目录、空录音丢弃、队列溢出丢弃；
- 路径安全（会话号白名单）；
- 页面双开关、播放/停止（自然结束不误报失败）、导出、单条删除联动删除录音；
- 仅录音条目按应用/日期展示、默认展开、播放/导出/删除，以及删除应用时联动删除；
- 存储层扫描、读取、导出、删除及快照不泄露路径；旧 manifest 无应用身份时归入「未知应用」。
