# 产品文案规范（用户可见文案）

本文件是**用户可见文案的唯一规范来源**：界面（Vue 页面 / 组件、`src/lib` 里的 label 函数）
与[用户手册](installation-and-configuration.md)面向用户的章节都按它执行。
[AGENTS.md](../AGENTS.md) 的「文档路由」指向本文件；名称与术语的具体要求不在别处重复。

## 1. 适用范围

- **适用**：页面与卡片标题、说明句、按钮、开关与标签、状态句、悬停提示、空状态、
  错误与重试提示、确认弹窗、安装器与更新流程里用户可见的文字、用户手册的面向用户章节。
- **不适用**：代码标识符与注释、`Testing/`、`Bugs/`、`docs/investigations/`、诊断日志，
  以及用户手册 §10「AI Agent 执行协议」（面向自动化与技术支持）。

## 3. 术语红线

**不得出现在用户可见文案里**（2026-10-01 Andy 明确）：注入、模拟按键 / 模拟按下、钩子、
报告层、HID / HID 路径、宿主（WUDFHost）、助手 / Helper、提权、计划任务、Raw Input、
ATVV、GATT / BLE / 无线电、内核 / 驱动、进程 / 端口 / 边沿、会话代次、队列 / 采样 / 帧、
状态机、白名单、令牌、结构化日志字段名。

**用户必须知情的内容照写，但说结果、不说机制**：

- 每次开启「全按键支持」都会弹一次授权窗口（2026-10-03 起）—— 写「系统授权」或
  「Windows 会弹出询问」，不写 UAC；
- VB-CABLE 安装需要管理员权限，装完要重启电脑；
- 个别游戏带防作弊保护，开启全按键支持后可能按键失灵、游戏打不开；
- 隐私：只读取这个遥控器的按键，不收集、不上传其他信息；
- 微信输入法语音识别需要联网、要求按住约半秒；遥控器按键默认行为；
- 服务方与技术名（蓝牙、遥控器、语音键、输入法、快捷键、Windows、VB-CABLE）。

## 4. 写法约定

- **一句一个意思**；状态句陈述现状，动作句以动词开头。
- 称呼用户用「你」，不用「本应用 / 该功能 / 用户」。
- **数字与拉丁词两侧加空格**：`左 Ctrl + 左 Win`、`小米蓝牙语音遥控器 2`、`约 0.5 秒`。
- 引用界面上的名称用中文双引号 “”（如“支持更多输入工具”“全按键支持”“是”）；
  「」只留给注释与文档。
- 按钮是动词短语（2–6 字）：扫描已配对设备 / 断开 / 更换设备 / 打开官方下载页。
- 未知与空状态给下一步，不给结论式抱怨：型号未读回先显示蓝牙名并等它读回。
- 错误提示说清「发生了什么 ＋ 你该怎么办」；不贴内部错误原文（必要的错误码进诊断摘要）。
- 同一设置出现在两处时，两处文案必须一致并互相指认（例：连接页「支持更多输入工具」
  = 按键页「全按键支持」）。
- 卡片说明一句话（≤ 40 字）；更长的解释放进「常见问题」折叠，不铺在首屏。
- **开关（Switch）一律放在对应文字右侧**：文字在前、开关在后，全应用一致
  （设置页「检查预览版更新」「登录时自动启动」，按键页「启用自定义按键功能」
  「全按键支持」「锁定当前按键」均为此写法）；不允许开关左置。
- **不可用项置灰必须给出原因与恢复方式**：功能未开启时，受它影响的控件整卡置灰、
  不可点击（含它的所有子操作），悬停提示说清「为什么不可用 ＋ 开启后恢复」；
  不允许只置灰不解释。当前唯一实例：「全按键支持」关闭时的返回 / 音量+ / 音量−
  三张卡片，悬停提示「返回 / 音量+ / 音量−需要开启全按键支持才能使用，开启后恢复正常」，
  开关开启后立即恢复正常可配置。
- **可能开启失败的开关：开关与状态提示合并成一个开关**（2026-10-10 Andy 定稿，
  以后同类开关一律照此）：不给开关配独立的状态字、状态圆点或状态句；开关只有
  **关闭 / 开启 / 正在操作**三态，进行中 = 置灰 + 转圈、不配任何文字；
  **只有失败才在开关旁显示一句文案**，且必须是普通用户能读懂的原因
  （说什么没成功 + 现在是什么状态 + 下一步怎么办），不出现 UAC、计划任务、退出码、
  组件文件名等内部细节（原文只进诊断日志）；其余情况一个字都不显示。
  现有实例：连接页“支持更多输入工具”与按键页「全按键支持」（同一个开关的两个入口，
  失败句里的名称随各页写法）。
- **本机根本用不了时，开关本身也置灰**（2026-10-07 起）：这时「开启后恢复正常」
  不成立，提示改成「原因 ＋ 新版本支持后会恢复正常」，并在开关旁给一句短说明
  （≤ 40 字）说清其它按键不受影响；被它控制的卡片同样置灰、同样不写「开启后恢复
  正常」。只说平台结果，不说内部机制（例：写「这台电脑暂不支持…」，不写架构或链路
  原因）。文案取值见 §7 的 2026-10-07 条。这条说明句属于**能力边界**，不随
  2026-10-10 的「其余情况不显示文案」删。

## 5. 落点与单一来源

- 用户可见字符串只允许出现在：`src/pages/*.vue`、`src/components/*.vue`、
  `src/lib/*.ts` 的 label 函数、`src/navigation.ts`、`docs/installation-and-configuration.md`。
- **原生兜底例外**：界面已经不工作时也必须能显示的原生文案写在 Rust
  （`src-tauri/src/lib.rs` 的托盘菜单项与「界面未能正常显示」的窗口标题）。
  改动它们同样要过 §6 清单，并在 §7 记一条决定。
- 同一概念只定义一次，其他地方引用（型号、按键名、阶段文案都走 label 函数）。
- 新增或修改用户可见功能时同步用户手册对应章节，并按 [AGENTS.md](../AGENTS.md) 检查 `TODO.md`。
