# Release Notes 规范（参照 macOS 端）

本文件参照 macOS 仓库 `HD838A/remote-mic-app` 的版本记录规范迁移而来，作为本仓库
撰写与更新 Release Notes 的常驻参照。原文载体：`Resources/zh-Hans.lproj/ReleaseHistory.md`
与 `Resources/en.lproj/ReleaseHistory.md`（提交 `b233a88cc4457b00413dda6b37ec8b4af12c5121` 起延续）。

迁移范围仅限「版本记录的写作与维护规范」，不含 Swift/SwiftPM、Sparkle、appcast、
公证或 CDN 等 macOS 专属发布机制；这些由本仓库 `RELEASING.md` 的 Windows 流程替代。

## 一、载体与结构

- 版本记录是**单一有序文件**，新版本**前置**插入，不改写历史条目。
- 结构固定为：一级标题（`# 版本历史`）+ 每版本一个二级标题 + 该版本条目列表。

```
# 版本历史

## 0.2.12（预发布）

- 条目一。
- 条目二。
```

- 版本标题格式：`## <语义版本>（预发布）`；正式版去掉括号限定词，只写版本号。
- 版本号按语义版本递增；版本被 Tag、Release 或分发资产占用时只递增 patch。

## 二、条目写作规则

- **一条一行**，以 `- ` 开头，同行写完，不换行、不嵌套子列表。
- **面向用户**，写用户能观察到什么变化，不写实现方式。
- **禁止出现的内容**：
  - PR 编号、Issue 编号、提交哈希、分支名；
  - 源文件路径、函数名、crate/module 名等内部标识；
  - 统计量、z 值、p 值、百分比等内部实验数据；
  - 内部术语与私有实现细节（如命名事件名、钩子名、注册表键名）；
  - 证书、私钥、密码、Token、设备身份、个人路径。
- **允许且鼓励的表述**：用户可见的改进、修复、新增能力、行为变化，以及
  「仍待验证」这类诚实的边界说明（用自然语言，不套用内部词汇）。
- 一组同类改动可合并为一条，但不得为了缩短而丢失用户可感知的差异。
- 内部入口、邀请码、隐藏手势、秘密版本号触发等**绝不可写入**；发布脚本应对其做
  拦截检查（macOS 端由 `prepare-public-release-assets.sh` 的正则门禁实现）。

## 三、聚合口径

- 每条记录描述的是「相对上一个**已发布**版本」的变化，而不是相对上一个版本号。
- 中间存在未发布版本时，按最后一个已发布版本聚合，不拆分出从未发布的条目。
- 只写已经合入发布源、且随本次分发包实际生效的改动；未合入或未启用的改动不写。
- 同一条改动同时出现在多个承载物（发布页面、应用内版本历史、关于页）时，措辞保持一致。

## 四、验证与边界的表述

macOS 端规范允许在条目内用一句自然语言说明未完成验证的部分。本仓库沿用该做法，
但在 Preview 正文中额外保留一个独立的「验证」小节，用来承载：

- 已实际执行并通过的自动检查；
- 依赖真实硬件或第三方应用、当前无法执行的部分，明确标为 **deferred**；

该小节是 Windows 端对 macOS 规范的**补充**，不是替代。它的目的是保持本仓库
`AGENTS.md` 的验证词汇约定（`passed` / `failed` / `deferred`）可追溯，
同时不让技术细节污染面向用户的条目列表。

## 五、变更纪律

- 版本记录通过普通 PR 合入，不直接改 main。
- Tag、Release 正文与资产一旦建立即视为不可变；内容需要变化时回到普通 PR，
  使用新版本，不覆盖旧 Tag 或旧资产正文。
- 更新版本记录时同步检查 `TODO.md` 对应条目，只有实现并完成验证后才能标记完成。

## 六、与 macOS 端的差异（有意排除）

| 项目 | macOS 端 | 本仓库 |
| --- | --- | --- |
| 载体 | `Resources/{zh-Hans,en}.lproj/ReleaseHistory.md` 双语 | 本文件为规范；正文载体见下节说明 |
| 本地化 | 中英各一份，逐条对应 | 当前仅有中文，未做英文本地化 |
| 发布机制 | Sparkle appcast + 公证 + CDN | NSIS + updater minisign（见 `RELEASING.md`） |
| 验证小节 | 不单列 | Preview 正文单列「验证」小节 |

> 载体说明：macOS 端的版本记录随 App 一起分发，因此放在 `Resources/`。
> 本仓库当前没有应用内「版本历史」界面，Release Notes 的实际载体是 GitHub Release 正文；
> 若未来新增应用内版本历史页，应在本仓库内新增对应资源文件，并按本规范维护。
